# Инвентарь синхронизации сетевого заезда

Документ отвечает на вопрос «что именно должно совпадать у хоста и клиента,
и что из этого уже сделано». Составлен по коду; обновлять вместе с протоколом.

Обозначения в таблицах:
- **OK** — у клиента есть то же, что у хоста (своими средствами или по сети).
- **~** — синхронизировано частично (видно, но чего-то не хватает).
- **нет** — у клиента этого нет.

## 1. Модель

- Хост — единственная авторитетная симуляция. Клиент **свою** машину
  моделирует локально для отклика и **ставит на хостовую позу при каждом
  снапшоте** (локальная симуляция заполняет промежутки). **Чужие** болиды ведёт
  по снапшотам с интерполяцией.
- Классы сущностей:
  - **A — гонщики.** Снапшоты 40 Гц (поза/скорость/поворот) + интерполяция;
    локальная машина применяется из снапшота сразу (`setPositionExact` +
    `setGlobalVelocity`), между снапшотами считается локально;
    `net_reconcile_local` — страховка на случай, если снапшоты пропали
    (снап >40 с восстановлением скорости). Телепорт-ловушка — отдельно, через
    синхронизированную фичу `STATIC_NULIFICATOR`.
  - **B — баллистика/фабричные тела.** Спавн с начальными условиями, дальше
    общая физика; клиентский визуал едет вместе со спавном (`netSpawn::client_link`).
  - **C — ходячие/самонаводящиеся.** Хост владеет позой и шлёт батчи состояния
    на 10 Гц; клиент **не** создаёт мировых акторов сам, ждёт спавн.
  - **D — косметика.** Общий сид `fxlabClientRND`, одни и те же эффекты
    воспроизводятся из одного потока, по сети не идут.

## 2. Каталог сообщений (`net_protocol.h`)

Транспорт/лобби: `PING`, `PONG`, `HELLO`, `WELCOME`, `ROSTER`, `READY`,
`START_GAME`, `LEAVE`, `KICK`.
Игра: `INPUT`, `SNAPSHOT`, `EVENT`, `SPAWN`, `DESPAWN`, `ACTOR_STATE`,
`GAME_OVER`.

## 3. Каталог событий (`netEventTypes`)

Используются:
- `NET_EV_ARCANE_CAST` — клиент просит хост скастовать; хост рассылает визуал.
- `NET_EV_ARCANE_INTERRUPT` — хост шлёт точку визуального прерывания.
- `NET_EV_ARCANE_STOP` — клиент просит хост остановить аркан.
- `NET_EV_ARCANE_STOP_VISUAL` — хост снимает клиентский визуал аркана.
- `NET_EV_ARCANE_LATCH` — аркан «прицепился» к жертве (VoodooMaster, 39).
- `NET_EV_HORN` — хост релеит гудок клиента остальным.
- `NET_EV_RACER_FINISHED` — хост релеит финиш гонщика (фанфары у чужих машин).
- `NET_EV_BONUS` — хост релеит подбор бонуса (фанфары у чужих машин).

**Объявлено, но не используется:** `NET_EV_RACER_DESTROYED`,
`NET_EV_RACER_RESPAWN`, `NET_EV_SLOT_TAKEN`, `NET_EV_CHAT`.

Поля `netEvent`: `type`, `slot`, `pos_{x,y,z}`, `part`, `arcane_id`,
`target_id`, `reserved`, `time_ms`. Заняты все, кроме `time_ms`.

## 4. Что уже синхронизировано (общее)

| Действие/событие | Механизм |
|---|---|
| Поза, поворот, скорость гонщиков | `SNAPSHOT`, интерполяция (A) |
| Локальный болид vs хост | ставится на хостовую позу на каждом снапшоте; между — локальная симуляция; снап >40 — страховка (`net_reconcile_local`) |
| Заморозка телепорт-ловушкой (жертва) | фича `STATIC_NULIFICATOR` в `features[]` снапшота |
| Точка телепорта (жертва) | `NET_EV_ARCANE_INTERRUPT` 058 (позиция), напрямую ставит локальную машину |
| Разрушение/сборка мехоса | `mech_state` в снапшоте |
| Мана и `Status` арканов по частям | `part_power[]`/`part_status[]` |
| Место/круг/чекпоинт гонщиков | `place/lap/checkpoint` в снапшоте |
| Время, звёзды, флаг «финиш» гонщика | `time_ms/nstar/flags` в снапшоте |
| Ввод клиента (тяга/руль/кнопки) | `INPUT`, батчи, `set_net_input` |
| Каст аркана клиента на хосте | `EV_ARCANE_CAST` |
| Визуал каста аркана (в т.ч. свой) | `EV_ARCANE_CAST` |
| Визуал прерывания (шторм/семя) | `EV_ARCANE_INTERRUPT` + позиция |
| Снятие визуала аркана | `EV_ARCANE_STOP_VISUAL` |
| Снаряды класса B | `SPAWN` (по типам + фабричные имена) |
| Мировые акторы класса C | `SPAWN` + `ACTOR_STATE` 10 Гц |
| Повторный спавн акторов вошедшему | `net_fx_resend_actors` |
| Старт заезда по тику | `START_GAME` + `ms_until_start` |
| AI по ростеру (слот занят/пуст) | `net_update_ai` |
| Косметический RNG | сид в `WELCOME` |
| Конец заезда | решает только хост; `NET_MSG_GAME_OVER` клиентам |
| Сигнал (HORN) чужого гонщика | `NET_EV_HORN` (хост релеит) |
| Финиш отдельного гонщика | `NET_EV_RACER_FINISHED` (хост релеит) |
| Подбор бонуса чужим гонщиком | `NET_EV_BONUS` (хост релеит, звук+эффект) |
| Запрет паузы/Pause в заезде | `mchNetQuant` + гард VK_PAUSE |
| Запрет выхода в меню по Escape | гард `MCH_KEY_EXIT` |

Важно: **любой объект зеркала, который должен сниматься по
`NET_EV_ARCANE_STOP_VISUAL`, обязан создаваться через `fxlabClientArcaneNew()`**
(она вешает метку owner/arcane) — иначе `fxlabClientArcaneStop` его не найдёт.
ShiftTrap (048, телепорт-ловушка) и MassShifter (058) создавались напрямую через
`fxlabClientD->CreateObject()` и потому «висели» на клиенте после срабатывания;
исправлено. Тем же дефектом страдали FireGarden (003, розы огня — «огненная
стена»), RageSlime (004, слизень), FuryFungus (005, плети+туман), FireStone (024)
и SnowFall (064, снаряд): их длительные модели тоже создавались напрямую и не
снимались — переведены на `fxlabClientArcaneNew()`.

Бонус-арканы (`fxlabBonusEvent`, не «кастуются» с части): **053** EnergyCharge,
**054** Jump, **055** Nitro, **062** SpellCharge, **063** AddStars, **067**
SpeedIncrement, **068** FireProtection, **069** Isolation, **070** Armor,
**071** BioPower. Их эффект — это состояние/свойство **самого** гонщика,
который ведёт хост; клиент видит результат через позу и снапшот. Своего
отдельного события для состояния не требуют, а звук/вспышка подбора у чужого
гонщика релеится событием `NET_EV_BONUS`.

Дефект подбора на клиенте (исправлен): гейт подбора в
`BonusMan::body_overlap_reaction` читает `body.averageSpeed() > 10`
(`bonus_man_mechos_hit_velocity`), а перепозировка своей машины снапшотом
каждые 25 мс (`net_apply_snapshot` → `setPositionExact` →
`Body::setPositionInit`) обнуляла `speed_avr` — EMA в `post_quant`
(0.06/кадр) не успевала нарасти между снапшотами, и клиентская машина
физически отталкивала бонусмена вместо подбора. Теперь средняя скорость
восстанавливается сразу после `setGlobalVelocity` (`setAverageSpeed`,
`net_game.cpp`), так что локальный подбор на клиенте снова работает — и
пропуск события `NET_EV_BONUS` для самого подбиравшего (слот равен
локальному) становится корректным, как и задумано.

Дефект эффектов подбора на клиенте (исправлен, второй проход): локальный
подбор сработал, но хост о нём не знал — `mchNetBonus` был no-op не на
хосте, а все реплицируемые поля читаются с хостовой копии машины. Для
маны (062) это выглядело как «пассивная регенерация перетирает подбор»:
каждые 25 мс снапшот возвращал `part_power` к значению хоста, где подбора
не было. Теперь `NET_EV_BONUS` ходит в обе стороны: клиент репортит свой
подбор (`mchNetBonus`, клиентская ветка), хост проигрывает его против
своей копии (`net_apply_client_bonus`): собирает мужика рядом с машиной
(`BonusMan::collect` — тот же телепорт `random(2048)`, что и локальный
подбор) или, если мужика нет в радиусе, применяет `AddBonus` без тела.
Окно дедупликации (500 мс, штамп в хостовой ветке `mchNetBonus`)
отбрасывает «двойника» — свой естественный подбор того же мужика, который
хост делает на несколько тиков позже. Энергия (053) на HUD — локальное
поле машины, снапшотом не перетирается и заполнялась локальным зарядом;
мана (062) — хост-авторитетна, теперь подбор до неё доходит.

Armor, **057** Insulation в обычном мире из `fxlabStart` не исполняются
(присутствуют только в demo/ином пути) — синхронизировать нечего.

## 6. Что ещё НЕ синхронизировано

1. **Оставшиеся поля `netRacerState`, которые есть, но не заполняются:**
   `part_arcane[]`, `bonus_count` + `netBonus[]`, `kind`. `part_kind[]`
   теперь заполняется и применяется: хост шлёт `M3D_KIND` каждой детали
   (без битов морфа/активации), клиент пересобирает машину под него, когда
   она собрана на хосте (`Mechos::net_sync_parts`). Это чинит
   «перемешанные» детали и заклинания: клиент собирается из ближайших
   свободных деталей, а его обломки разлетаются по своему RNG, поэтому
   набор деталей (и арканы на них) мог отличаться от хозяйского — и
   `net_apply_event` на хосте разрешал каст по индексу детали на *своей*
   машине, то есть стрелял не тем заклинанием, что задумал клиент.
   `features[3]` теперь шлётся (из него читается `STATIC_NULIFICATOR`), но
   применяется пока только этот бит. Для HUD/визуала удалённых машин
   остального не нужно: визуальные фичи приезжают событиями арканов.
2. **Семена (маршрутные точки) удалённых машин.** Не шлются. В аркадном
   сетевом заезде семена — это AI-маршрут без собственного меша; виден лишь
   аркан-ловушка на семени, а их в заезде без фазы планирования нет, так что
   визуально терять нечего. Пересмотреть, если появится фаза планирования.
3. **Чат.** `NET_EV_CHAT` объявлен, не реализован.
4. **Кнопки-команды (`NET_BTN_ARCANE_REMOVE`, `NET_BTN_MAP`,
   `NET_BTN_CENTER_VIEW`).** Карта и центровка камеры идут локально
   (`mchKeyTrap`), хосту не нужны. Снятие аркана/семени меняет семена, а они в
   аркадном заезде — AI-маршрут (см. п.2), поэтому расхождения не видно.
5. **Промежуточный урон удалённых машин.** Клиент видит итоговый `mech_state`
   (взрыв/сборка) и энергию из снапшота, но отдельного HUD здоровья для чужих
   машин в игре нет — рисовать нечего.
6. **Точки управления / семена AI.** Хост-локально; клиенту не нужны (позу
   чужих машин ведёт снапшот).
7. **Погода/время суток.** Не синхронизируются (пока константа мира).
8. **Бонусмены после подбора на стороне хоста.** Подбор телепортирует мужика
   в `random(2048)` (`BonusMan.cpp`), а не убивает его — деспавна нет. Если он
   приземлился дальше `NET_ACTOR_SPAWN_RADIUS`, хост перестаёт слать состояния,
   и клиент навсегда остаётся с устаревшим экземпляром (толкается, не
   подбирается); в кольце 1200–2400 защёлка `spawn_sent` не даёт обновлений
   состояния после первого спавна. Нужен явный деспавн/респавн или снятие
   радиусного отсечения для уже заспавненных акторов.
   (Репорт подбора с клиента теперь тоже телепортирует мужика на хосте —
   `net_apply_client_bonus` — но радиусное отсечение это не отменяет.)

## 8. Пост-гоночный экран сетевого заезда (сделано)

Раньше после финиша у сетевых игроков ничего не происходило: мехос оставался
под управлением игрока, экрана итогов не было, музыка не менялась. Две причины,
обе исправлены:

1. **Матч не переходил в завершённое состояние.** `mchEndGame` ставил
   `mchTimeMode = MCH_TIME_GAME_OVER`, но `netMatch::state()` оставался
   `NET_MATCH_RUNNING`, и `mchNetQuant` на следующем кадре возвращал время в
   `MCH_TIME_RUNNING` — экран итогов тут же снимался, а машины снова уходили под
   игроков. Добавлен `netMatch::finish()` (хост зовёт из `mchNetGameOver`, клиент
   — из `net_apply_game_over`), после чего навязывание стартового тика не
   срабатывает.
2. **Кнопки выхода не было.** Каждый трек объявляет `part` (у дефолтного
   `water0` — 59), поэтому `mchA_TrackPart` был ненулевым, и на экране итогов
   ветка «купить деталь» перекрывала кнопку Continue — выйти в меню было нечем.
   В сетевом заезде приз не выдаётся: `mchA_TrackPart = 0`.

Заодно: после финиша поле целиком уходит под ботов (хост —
`net_endgame_ai`, клиент — `mchEndGame` для своей машины), снапшоты продолжают
идти, чтобы клиенты видели то же поле; выход с экрана итогов возвращает в главное
меню и снимает сетевую сессию (`mchNetFinit`). Проверяется вручную
`-netfinish <сек> [-netleave]`.

Про «главное меню»: это именно стартовое меню (SCR0/1/2 — то, на котором есть
строка «СВЯЗЬ»), а не iWorld-остров (мир 7), куда уходит одиночная игра. Раньше
выход с итогов вёл в мир 7. Теперь и кнопка Continue на итогах, и «Выход» в
Escape-меню зовут `mchNetPrepareMainMenu()` и уходят в `RTO_MAIN_MENU_ID` с
`mch_iScreenID`, выставленным по числу сохранений (как `mchFinitDemo` /
`mchInitOutro`); `mchCurrentWorld` при этом остаётся на проеханном мире, чтобы
меню сети по-прежнему предлагало его по умолчанию.

## 9. Приоритеты (предложение)

1. Чат (`NET_EV_CHAT`).
2. Оставшиеся поля снапшота (`features`/`part_kind`/`part_arcane`/`kind`) —
   если понадобятся для HUD.
3. F2/F3-крэш меню.
